# ARCH-053-WOOCOMMERCE-008 — Private outreach-coupon outcomes and optional stacking choice

## Architecture

`ARCH-053` — `docs/architecture/ARCH-053-woocommerce-checkout-recovery-links-and-cart-restoration.md`, coordinated by `moda_architect`. Materialised. Attempt 1 received Changes Requested; Attempt 2 is submitted for Architect Review.

## Objective

Provide an **optional, non-error** choice when a confirmed promotional coupon cannot coexist with the valid original coupons, while keeping all Moda-originated coupon-rejection, resolver and unexpected restoration **errors off the merchant storefront**. WooCommerce totals and truly applied coupons remain authoritative in Classic and Blocks.

## Context

WOOCOMMERCE-006 privately handles original coupon rejections and contains native Woo error notices generated by the plugin's automatic attempts. WOOCOMMERCE-007 returns typed private outcomes of attempting the **confirmed initial WhatsApp offer**. This task owns only the protected, one-time customer choice for a verified stacking conflict and containment of further coupon errors. It is not a second offer selector or a general public error presenter.

## Scope

Only `moda-interact-woocommerce`:

- **Create** `includes/Checkout/CheckoutOutreachCouponChoice.php`: WC-session-scoped, single-use conflict-choice state and a protected same-origin checkout POST action. No bearer token, customer data or recovery URL in HTML/POST/query fields.
- **Create** `includes/Checkout/CheckoutOutreachOfferChoicePresenter.php` for a **non-error, optional offer-switch control only** in Classic and supported Blocks. It may describe the two valid alternatives without claiming guaranteed savings, but MUST NOT display a rejected/expired/failed/unverifiable Moda notice, stack trace, API response or PHP warning.
- **Update** `includes/Checkout/CheckoutResumeController.php` to feed the typed WOOCOMMERCE-007 result into the server-side choice state on a **successful confirmed restore** only. No choice state on link-preview GET or unsuccessful/unsupported restore.
- **Update** `includes/Checkout/CheckoutCouponOutcomeHandler.php` from WOOCOMMERCE-006 to privately record and contain error notices produced by automatic recommended-coupon attempts and protected choice retries. Preserve unrelated shopper and merchant Woo notices.
- **Update** `includes/Runtime.php` for the narrowly scoped choice action/UI surface; register Blocks assets only if essential to the **non-error choice** and proven on actual Woo Blocks. Add PHPUnit and real Classic/Blocks tests.

## Out of Scope

No ARCH-052 offer discovery or new coupon creation, no Moda-generated error/expiry/unverifiable messages after cart display, no alternate Woo cart restoration, new API version, unauthenticated link resolution, new storage table, production WhatsApp send switch or global Woo notice removal.

## Requirements

### Multi-code confirmed offer group — private failures and safe choice

- Consume WOOCOMMERCE-007's bounded v1 `CHECKOUT_OFFERS` group (2..3, as defined by the accepted Shared contract), plus existing code, automatic, alternative and no-offer variants; never infer codes from message text or mutable merchant settings.
- `APPLIED`/`ALREADY_APPLIED`: Woo's actual applied coupons and current calculated total are shown through normal Woo checkout UI; no extra Moda notice.
- `REJECTED`, partial/group rejection, expired, `NONE/UNVERIFIABLE`, `AUTOMATIC_NOT_FORCED` or `NOT_APPLICABLE`: record bounded outcomes in **server-side** diagnostics, leave the actually valid coupon set and current totals intact, and display **no Moda-generated error or informational rejection notice**. Never claim offered savings were applied when they were not.
- If a verified offered code/group conflicts with an otherwise valid original set, restore the successfully applied original set and, **only if both alternatives can be safely represented**, offer an optional non-error “Try the offered set instead” control. The default is **keep original coupons**; never automatically remove them or display a failure banner. This control is not a technical or coupon-error message.
- Choice record is restricted to current WC session: `moda_interact_outreach_coupon_choice_v1`, with `{recoveryId, codes: string[1..3], originalCodes, cartHash, createdAt}` (plus checkoutKey only if necessary for stronger session binding). Ten-minute maximum lifetime; invalidate on cart change, checkout state change, order completion, new restore, successful/failed use or expired nonce. Never persist codes in a WordPress option, browser localStorage or client POST/query.
- POST `moda_interact_outreach_coupon_choice=try_offered` must verify Woo session, server-created state, valid WordPress nonce, same origin, current cart fingerprint and original checkout/recovery generation. Double submits become no-ops. Stale/tampered requests leave the cart as-is and produce **private** diagnostics, no Moda checkout notice.
- On explicit offer-switch POST, revalidate the **entire** confirmed set with native Woo rules. On any rejected or partially applied code, attempt restoration of the previously successful original set, recalculate, clear only Woo error notices created by *this automatic attempt* and render no Moda error. On unexpected failure, use the guarded rollback and safe storefront redirect from WOOCOMMERCE-002; log the original safe dependency error privately, never claim success.
- Preserve unrelated WC notices (including shopper-entered coupon validation), correctly applied discounts, consent/STOP/order/generation fencing and ordinary merchant checkout totals. Never use global `wc_clear_notices()` or modify merchant WordPress debug settings to suppress Moda errors.
- WordPress PHP must not import `@modainteract/moda-interact-shared/logging`; only hosted Moda Node services use that Shared npm module. Follow the plugin's current bounded private server-side `error_log()` convention and redact coupon values, full links, bearer tokens and customer details.
- Observe the dedicated task worktree and repository ownership protocol, with no `_index.md`, ARCH-052 task edits or unrelated refactors; only the repository agent updates its task Completion Report and stops for architect review.

**Server-side WC session-only example after a successful confirmation and verified conflict:**

```php
[
    'recoveryId' => 'recovery_456',
```

**Client POST contains only the action and nonce:**

```text
POST <merchant checkout page>
moda_interact_outreach_coupon_choice=try_offered
_wpnonce=<session-bound action nonce>
```

**Customer-visible matrix:**

| Result | Storefront behaviour | Server-side handling |
|---|---|---|
| APPLIED / ALREADY_APPLIED | Standard Woo applied codes and true total; no Moda notice | Record successful outcome |
| REJECTED / GROUP_REJECTED / partial / expired | Current Woo coupons and total; no Moda notice | Record bounded rejection, restore any original set |
| Verified stacking CONFLICT_REQUIRES_CHOICE | Keep original valid set by default; optional **non-error** offer-switch action | Session-bound state, single use |
| AUTOMATIC_NOT_FORCED / NOT_APPLICABLE / NO_OFFER | Standard Woo cart and totals only | No fabricated applied coupon |
| UNVERIFIABLE / dependency failure | Standard safe cart/checkout fallback; no Moda notice | Record original redacted dependency error and bounded reason |
