# ARCH-014-DATABASE-002

## Objective

Add the missing **merchant-facing plan-card highlight** persistence required to render the pricing cards agreed for ARCH-014.

A highlight is presentation content such as:

```text
Included capacity
100 monthly recovery conversations.

Subscriber top-up rates
Get better pricing than Free when you need more.

Priority support
Fast help for higher-volume merchants.
```

Highlights are **not Shopify usage events** and MUST NOT be stored in `MerchantPricingUsageEvent`. Usage events remain economic/provider-pricing evidence. Highlights are merchant-facing localized card content.

This task is the only new prerequisite required before `ARCH-014-ADMIN-004` and `ARCH-014-SHOPIFY-002`. Once this task is architect-accepted and integrated, those two tasks are intentionally independent and may execute in parallel.

## Binding GPT-5.6 Luna implementation rule

Do not redesign ARCH-014. Implement the exact new models, constraints and validation below. Do not infer a different content model. Do not merge highlights into usage events, plan descriptions, static i18n or operational `BillingPlan` data.

## Existing-table isolation rule

The database change remains additive-only.

**MUST NOT modify any existing database table.** In particular, generated migration SQL MUST NOT contain:

```sql
ALTER TABLE "billing"."MerchantPricingPlan"
ALTER TABLE "billing"."MerchantPricingPlanTranslation"
ALTER TABLE "billing"."MerchantPricingUsageEvent"
ALTER TABLE "billing"."MerchantPricingUsageTier"
ALTER TABLE "billing"."BillingPlan"
```

or `ALTER TABLE` for any other pre-existing table.

One Prisma-schema-only change to the existing `MerchantPricingPlan` model is allowed:

```prisma
highlights MerchantPricingPlanHighlight[]
```

This is a virtual inverse relation field and MUST generate **no column, index, constraint or ALTER TABLE statement** on `billing.MerchantPricingPlan`.

The foreign key is owned by the new child table and may be added by altering the newly created `MerchantPricingPlanHighlight` table.

Do not edit any pre-ARCH-014 enum or operational billing model.

## Exact Prisma model additions

Edit:

```text
prisma/schema.prisma
```

Add the inverse relation field above to `MerchantPricingPlan`, then add these two new models in the existing `billing` schema:

```prisma
model MerchantPricingPlanHighlight {
  id                    String   @id @default(cuid())
  merchantPricingPlanId String
  merchantPricingPlan   MerchantPricingPlan @relation(fields: [merchantPricingPlanId], references: [id], onDelete: Cascade)

  contentKey String @db.Uuid
  position   Int

  translations MerchantPricingPlanHighlightTranslation[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([merchantPricingPlanId, contentKey])
  @@unique([merchantPricingPlanId, position])
  @@index([merchantPricingPlanId])
  @@schema("billing")
}

model MerchantPricingPlanHighlightTranslation {
  id                             String @id @default(cuid())
  merchantPricingPlanHighlightId String
  merchantPricingPlanHighlight   MerchantPricingPlanHighlight @relation(fields: [merchantPricingPlanHighlightId], references: [id], onDelete: Cascade)

  locale              String @db.VarChar(16)
  merchantTitle       String @db.VarChar(120)
  merchantDescription String @db.Text

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([merchantPricingPlanHighlightId, locale])
  @@schema("billing")
}
```

Do not add another plan identifier, plan name, Shopify handle, price, allowance or usage-event column to these tables.

`contentKey` is a stable UUID generated by the Admin builder before persistence. It is the language-independent identity used by the translation JSON package. Reordering a highlight changes `position`, not `contentKey`.

## Exact deferred integrity

Add ARCH-014-owned deferred validation that runs only on the two new highlight tables.

At transaction commit, each surviving `MerchantPricingPlanHighlight` MUST satisfy:

```text
exactly 20 MerchantPricingPlanHighlightTranslation rows
exact locale set above
all titles valid
all descriptions valid
```

For each plan that has highlights, highlight positions MUST be exactly contiguous:

```text
0..N-1
```

No gap and no duplicate position is valid.

Use deferred constraint triggers so Admin may atomically:

```text
delete/rebuild highlights
insert highlight rows
insert all 20 translations per highlight
commit
```

without an intermediate statement being rejected before all children have been inserted.

Create functions with these exact responsibilities (names may use the repository's existing ARCH-014 naming style, but do not combine them with operational billing functions):

```text
validate one highlight translation-completeness state
validate one plan's highlight-position state
trigger adapter for MerchantPricingPlanHighlight
trigger adapter for MerchantPricingPlanHighlightTranslation
```

Do not change the existing `billing.validate_arch014_merchant_pricing_plan(...)` semantics merely to implement highlights. Highlight completeness is enforced by the new highlight-specific functions/triggers.
