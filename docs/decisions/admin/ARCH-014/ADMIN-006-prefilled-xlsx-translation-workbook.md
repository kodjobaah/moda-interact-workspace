# ARCH-014-ADMIN-006

## Objective

Replace the **human-facing** ARCH-014 translation JSON workflow with a pre-populated `.xlsx` translation workbook.

The administrator/translating user MUST NOT be asked to construct JSON, preserve UUID keys, remember locale codes, or reproduce a schema manually.

The workbook generated by Moda MUST already contain every piece of information Moda knows before translation begins:

- all exact 20 supported locales;
- a normal human-readable language label for every locale;
- every exact locale code;
- the current plan name and Shopify plan handle;
- the current English plan description;
- every current ordered highlight and its English title/description;
- every previously stored translation that is still valid for the current English source;
- blank cells only for translations that genuinely need to be supplied or re-supplied.

The user workflow becomes:

```text
finish English merchant content
        ↓
Download pre-populated translation spreadsheet
        ↓
fill only missing translation cells
        ↓
Upload or drag/drop completed .xlsx
        ↓
Moda converts workbook -> canonical translation schema v2
        ↓
existing parseCompletedMerchantPricingTranslationPackage(...)
        ↓
20 / 20 validation
        ↓
existing final Save/Create flow
```

The accepted schema-v2 JSON contract remains the **internal canonical validation/persistence contract**. It is no longer a normal Admin editing surface.

## Binding GPT-5.6 Luna rule

## Pre-population behavior — existing plan

Reuse the accepted ADMIN-004/005 retention rules. Do not implement independent retention logic inside the workbook layer.

The builder MUST construct the canonical template package first using the existing accepted template/retention behavior, then the workbook generator renders that package.

Therefore:

```text
unchanged plan description
  -> all existing 20 descriptions pre-populated

changed plan description
  -> new English description pre-populated
  -> the other 19 plan-description cells blank

unchanged existing highlight source
  -> all stored 20 title/description translations pre-populated

changed existing highlight title or description
  -> current English source pre-populated
  -> the other 19 title/description cells for that highlight blank

new highlight
  -> English title/description pre-populated
  -> the other 19 title/description cells blank

removed highlight
  -> no columns for that highlight

reorder-only highlight edit
  -> columns follow current new order
  -> all existing translations remain pre-populated because contentKey identity did not change
```

This requirement is binding. Do not blank all translations merely because one source element changed.

# Cell-value safety rules

For every used translation text cell:

- blank/null is converted to `""` and allowed to reach the canonical parser as incomplete translation content;
- a plain string is accepted;
- leading/trailing whitespace may remain in workbook readout because the canonical parser already normalizes for validation;
- numeric, boolean, date, rich-text object, hyperlink object, formula object or another non-string value is a workbook-structure error;
- NEVER evaluate formulas;
- NEVER use a formula result as translated content.

Use issue code:

```text
UNSUPPORTED_CELL_VALUE
```
